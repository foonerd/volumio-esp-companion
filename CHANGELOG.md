# Changelog

All notable changes to Volumio ESP Companion are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

- `boards/waveshare-esp32-c5-touch-lcd-28`: the board's bring-up (expander, ST7789 panel, CST3530 touch, backlight, the shared SPI and I2C buses) moved out of the firmware into a library crate, `companion-board-waveshare-esp32-c5-touch-lcd-28`, so a second firmware can stand on the board; `Board` now hands out the I2C bus for a codec or a DAC. The companion firmware is unchanged in behaviour. Excluded from the host workspace like `platform/esp-idf`; `check.sh` formats and lints it through the firmware.
- `drivers/es9018k2m`: the ESS ES9018K2M stereo DAC as Pi HATs carry it (LightSABRE, I-Sabre K2M class): detection by the status register, the bring-up sequence, volume on the plugin's 0 to 100 curve, mute. Register sequence from es9018k2m-plugin (MIT). `no_std`, four tests, bare-metal in `check.sh`. Not yet on a board.

## [0.1.0] - 2026-10-18

First release: the Waveshare ESP32-C5-Touch-LCD-2.8 runs the player's face, configured by a microSD card.

- Fast boot: after a join the firmware remembers the access point's channel and BSSID and goes straight there next time, about three seconds to an address; the face at seven seconds instead of eighteen. A hint that does not answer within ten seconds falls back to the full search, which keeps the complete scan so the first join picks the strongest BSS.
- Release workflow (`.github/workflows/release.yml`): a `v*` tag runs the full check, builds the image, refuses a tag that does not match the firmware crate's version, and publishes the image, its parts, `SHA256SUMS` and the card template with the install steps for Windows, macOS and Linux as the release notes. A manual run builds and uploads without publishing.
- `name` in `volumio.txt`: the device's network name (a DNS label of up to 30 letters, digits and hyphens), given to DHCP so the router's device list shows it; default `espressif`. The face prints the bare name: there is no mDNS responder in the build yet, so a `.local` suffix would name something that does not answer.
- First runs with a card and a player. The face came up and the board rebooted every 31 s: the album-art thread overflowed its 48 KB stack inside the JPEG decoder (the desktop measurement was 1.5 KB short of the device). The thread's stack is now 256 KB in PSRAM and the heartbeat reports its low-water mark. The Wi-Fi scan, a bring-up diagnostic, runs only when no network is set, which takes 12 s off every boot. Seen on the board: the cover, a tap, a swipe.
- Configuration by microSD card. The device reads `volumio.txt` from the card's root on every boot (`key = value`, the settings store's names plus `wifi_ssid` and `wifi_password`), writes it into NVS, joins the network it names, and writes `status.txt` back with what it is, what it applied, what it did not understand and whether the network was joined, never the password. The template is `sdcard/volumio.txt`. The parser is in `companion-runtime` (`card`, host-tested, including the shipped template); the card itself is `platform/esp-idf`'s `Card` over ESP-IDF's SD-SPI host and FatFs on the panel's SPI bus, now shared through an `Rc`; the simulator reads the same file with `--card PATH`. The build-time `WIFI_SSID`, `WIFI_PASS` and `PLAYER` are gone: one image, configured by card. FAT32 only (FatFs in ESP-IDF 5.5 has no exFAT); long file names on. Bench: with an empty slot the card step is one line and 50 ms.
- `scripts/check.sh` removes an esp-idf-sys CMake build cache that was configured against a different ESP-IDF version than the crate pins; such a cache, restored by CI's nearest-key fallback or left on a workstation after the pin moved, fails the build on the old tree's missing toolchain file.
- `firmware/waveshare-esp32-c5-touch-lcd-28`: first boot on the board: Wi-Fi driver up, both bands scanned, panel lit, face drawn, touch armed, heartbeat. Two fixes got it there. ESP-IDF pinned to v5.5.5: v5.5.6 added `wifi_task_stack_size` to the Wi-Fi init config and esp-idf-svc 0.53.0 does not set it, so the Wi-Fi task was created with no stack and `esp_wifi_init` failed with `ESP_ERR_NO_MEM`. And the firmware keeps going without a network when the Wi-Fi driver will not start: the panel lights and the status page says offline instead of a boot loop. The memory report now gives free and largest-block figures, which is what a failed allocation needs.
- `firmware/waveshare-esp32-c5-touch-lcd-28`: first bench run. The board flashes and the bootloader runs; the app did not boot because ESP-IDF's "single app large" partition is 1500 KB and the app is 1.9 MB, a size the changelog below had wrongly called a 3 MB partition. The crate now carries `partitions.csv` with a 3 MB app partition; `scripts/image.sh` generates the table from it and refuses an app that would not fit. `PLAYER` build-time setting seeds the player's address into the store on first boot.
- `drivers/es8311`: the audio codec on Waveshare's ESP32 touch panels, DAC path, at `0x18`: open, format (rate and width from the clock table, master clock made from the bit clock as the board has no MCLK), start, suspend, mute, volume in half-decibels with the reference's 0 to 100 curve and the board's hardware gain; `bit_clock_for` says what the I2S side must produce. From Espressif's `esp_codec_dev` in the BSP's configuration. `no_std`, 13 tests against embedded-hal-mock, built for bare-metal RISC-V in `check.sh`. Not yet on a board. For the player project's output; the companion makes no sound.
- `art`: album art fetched and decoded on a thread, generic over the HAL's HTTP client, carried out of the simulator so the firmware shares it. `spawn` for a desktop, `spawn_with_stack` for a device; `DEVICE_THREAD_STACK` measured on the host in release. The firmware fetches covers into PSRAM and draws them; the simulator uses the same crate.
- `firmware/waveshare-esp32-c5-touch-lcd-28`: the board brought up (`src/board.rs`) in the vendor BSP's order through `ch32v003-expander`, mipidsi's ST7789 over SPI2 and `cst3530` on the shared I2C bus, and `companion-runtime`'s `App` run on the panel: status page, face, touch, with the backlight lit after the first frame. Album art and audio not yet. App 1.9 MB in a 3 MB factory partition. Not yet seen on a board.
- `platform/esp-idf`: `Http` over `esp_http_client` with the certificate bundle, `NvsStore` over NVS (a key over 15 bytes is refused, not truncated), `WifiNet` wrapping the blocking Wi-Fi as `NetworkStatus`. No `unsafe`; built inside the firmware's workspace. The firmware joins the network through it, reads its settings from the NVS namespace `companion` and asks the player for `/status`.
- `runtime`: the settings keys respelled to fit NVS's 15-byte names (`text_portrait`, `gap_portrait`, `strip_portrait`, `debounce_ms` and their landscape pairs); `key::ALL` and `key::MAX_KEY_LEN`, with a test holding every key to the limit. Nothing had shipped under the old spellings.
- `drivers/ch32v003-expander`: the IO expander on Waveshare's ESP32 touch panels (eight GPIO, PWM, ADC at `0x24`), from Waveshare's register map and BSP sequences, with a shadow of the write-only registers. `drivers/cst3530`: the touch controller at `0x58`, implementing `TouchSource`, from Waveshare's `esp_lcd_touch_cst3530` component. Both `no_std`, over embedded-hal 1, tested against embedded-hal-mock, built for bare-metal RISC-V in `check.sh`. Neither has met a board yet.
- `sim`: the application on a desktop. `ureq` for the player, the host's interfaces for the status page, the command line as the settings store, a thread for album art (JPEG and PNG through `image`), SDL2 for the panel and the finger behind a `window` feature; `--snapshot` renders to a PNG without a window or a library. Verified against a live Volumio in both orientations. `check.sh` runs the headless shape and keeps the PNG; CI uploads it.
- `runtime`: the application, carried over from rpi-waveshare28 `main.rs`, `input.rs` and the fetching halves of `state.rs`, `art.rs`, `http.rs` and `config.rs` at `61ecf6d`. The Pi's loop, threads and channels become a state machine a device steps with its own clock: `App::touch`, `App::step`, `App::art_request` / `App::art_arrived`. The gesture derivation, the Volumio REST client, the album-art gate with its backoff, the settings keys and the request-target encoding come with their tests (37). `no_std` with `alloc`; builds for bare-metal RISC-V, which `scripts/check.sh` now proves for it too.
- `core`: `PlayerState::parse`; `StatusText`, `BarGap` and `Strip` gain the `as_str` / `parse` pair `Theme` had, for the settings store.
- `hal`: the traits a device implements (touch source, HTTP GET, config store, network status, player discovery, frame present) and the capabilities record a firmware declares as a const. `no_std` with `alloc`.
- `core`: the pages, the transient surfaces, the player state model and the Volumio command shapes, carried over from rpi-waveshare28 at `61ecf6d` with their 48 tests. `no_std` with `alloc`; the fetching and the settings stay in the runtime. Builds for bare-metal RISC-V, which `scripts/check.sh` now proves.
- `firmware/waveshare-esp32-c5-touch-lcd-28`: the first firmware, std Rust on ESP-IDF v5.5.6. On boot it reports the chip model and revision, the PSRAM and heap sizes, a dual-band Wi-Fi scan with each access point's band, channel, strength and auth, an optional connection when credentials were given at build time, and a heap heartbeat every five seconds. No panel, touch or audio yet.
- `core` and `hal`: the two shared crates laid down as enforced contracts (`no_std`, no `unsafe`, no platform crate), empty of code until the port.
- `scripts/check.sh`: format, clippy, tests and docs on the host workspace, the scripts, then every firmware crate built; refuses to pass without the ESP toolchain. `scripts/image.sh`: the merged image and its parts into `dist/` from the offsets ESP-IDF writes to `flasher_args.json`.
